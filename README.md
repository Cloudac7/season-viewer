# 四时 · 中国季节地图

React + TypeScript + Vite 前端，以 Open-Meteo 日均气温、真实 DEM 地形和滑标参考规则显示全国春夏秋冬与换季过程。

地图只保留“季节分布 / 滑动均温”两个图层。季节使用固定四季色和按方向区分的两级换季色；切换均温时自动隐藏换季叠色和图例。默认不显示县界白线，县界仍可打开并用于搜索定位。县级、地级数据表独立保留。

## 运行与发布

需要 Node.js 20.19+ 或 22.12+。

```sh
npm ci
npm run dev                    # predev 自动预计算，默认 http://127.0.0.1:5173/
npm test                       # 判季、时效、缺测、区划、二进制与曲面几何测试
npm run build                  # prebuild 预计算 → TypeScript/Vite → 精简发布资产
npm run deploy:cloudflare      # 构建并用 Wrangler 部署到 season.tomori.xyz
npm run preview                # 预览 dist/，只读取静态快照
npm run data:precompute        # 离线预计算；资料/算法未变时复用缓存
npm run data:refresh           # 更新县级和规则气温，随后生成新发布快照（需联网）
npm run data:grid:update       # 只更新独立规则气温快照
npm run data:counties:update   # 只更新县级代表点快照
npm run data:grid:import       # 重新生成独立天气采样目录
npm run data:terrain:import    # 导入公开 Terrarium DEM（需联网，原始瓦片缓存）
```

`data:refresh` 遇上游失败会停止后续下载，仍尝试用已有资料生成可用快照，错误以退出码报告。429 不循环重试或绕过配额。正式静态部署需由部署环境每日运行 `data:refresh` 再执行 `build`、发布 `dist/`；浏览器不会直接向 Open-Meteo 发起全国 API 请求。静态托管本身不会获取新天气，页面保留真实资料时间。

Cloudflare 部署使用 Wrangler 与 Workers Static Assets。首次使用前执行 `npx wrangler login` 完成 Cloudflare OAuth；`npm run deploy:cloudflare` 会重新构建（包含每日快照预计算），再将 `dist/` 部署到配置的 `season.tomori.xyz` 自定义域。Cloudflare 账号须包含并启用 `tomori.xyz` zone，且该子域尚未绑定其他 CNAME/服务；Wrangler 会为 Workers 自定义域建立 DNS 记录并申请证书。后续每次天气资料刷新后重新运行此命令即可发布新快照。

## 每日自动更新

GitHub Actions 工作流 `.github/workflows/daily-weather.yml` 每天北京时间 09:00（UTC 01:00）计划运行，也可在 GitHub Actions 中手动触发。GitHub 的计划任务可能排队延迟。工作流从线上快照或上次运行的缓存恢复县级和格点历史、配额及限流状态，下载最新资料，完成预计算后部署并校验线上版本。失败的下载会保存已完成的断点并停止部署；可在 Actions 页面查看错误并手动重试。缓存被清理后，工作流会从当前线上快照重新接续。

启用前，在仓库 Settings → Secrets and variables → Actions 添加 `CLOUDFLARE_API_TOKEN`。可在 Cloudflare 创建限制到本项目账号和域名的 Workers 部署令牌，使用 **Edit Cloudflare Workers** 模板；令牌值只保存在 GitHub Secret，不要提交到仓库。工作流使用已配置的 Cloudflare 账号 ID。操作完成后在 Actions 中运行一次 **Refresh and deploy weather**，确认抓取和部署成功。

## 计算前移与缓存

此前页面打开时在 Worker 中重算约 22.8 万个显示格点；现在全国分类、县级统计、地级汇总和地图轮廓都在部署/构建时生成。

1. 读取并校验已保存的气温、地形和行政边界，确定有连续 9 个完整日的日期范围（最多 30 个日期）。首次 14 天历史通常可生成 6 个可用日期。
2. 对每个日期预计算季节、日温、滑温、换季与预报结果，打包为二进制；同时准备县级与地级统计、平滑 SVG 曲面、行政归属索引。
3. 原始资料、判季/投影/曲面源码及北京日期共同确定版本哈希。同一版本直接跳过，进程锁避免并行重复生成。
4. 在临时目录完成全部文件，原子发布不可变版本目录，最后更新 `manifest.json`。发布期间页面继续读取上一份完整快照。
5. 页面按所选日期获取二进制和曲面，按版本缓存；点击详情仅做一个格点的轻量插值与曲线计算，不再计算全国场。行政标题是预计算索引查表，无前端全国多边形遍历或外部反地理 API。

输出位于 `public/data/precomputed/`，由构建重建并被 Git 忽略。`postbuild` 仅在 `dist/` 中保留当前发布版本，开发缓存不受影响，已打开页面仍可读取旧版本资产。生产建议启用 Brotli/gzip；不可变版本文件适合长期缓存，manifest 应使用短缓存/重新验证。

本次 6 日期首次预计算约 20 秒；哈希一致时跳过约 0.05 秒。这是本机测量，页面实际加载还受网络与设备影响。最新日期的二进制约 3.1 MB（gzip 约 0.84 MB），矢量图约 2.2 MB（gzip 约 0.73 MB）；点击资料与行政索引并行加载，不阻塞地图。北京跨日或预报过期时，会自动切换到预先生成的无预报叠色资产。

本地开发 `GET /api/precomputed-spatial` 返回 manifest，并在资料改变、北京跨日或周期检查时后台运行共享刷新流程。生产没有该接口时自动读取静态 manifest。缺少发布资料时明确提示并重试，不退回前端重算或模拟天气。

## 地形气温场

参考气象业务先分析成格点场再分级填色的处理顺序：[中国气象局多源格点融合产品说明](https://www.cma.gov.cn/2011xwzx/2011xqxkj/2011xkjdt/202205/t20220518_4835961.html)。本项目未接入或冒充官方多源实况融合产品。

- 独立气温采样：WGS84 规则格网 **1°、1,265 点**，包含中国陆地及相邻插值缓冲，不以县中心代替规则天气节点。
- 地形：**0.1°、631×361**，来自 117 张真实 z6 [AWS Terrain Tiles](https://registry.opendata.aws/terrain-tiles/)，按 [Terrarium 官方格式](https://github.com/tilezen/joerd/blob/master/docs/formats.md) 解码并面积重采样，记录来源、时间和原始瓦片 SHA-256。陆海遮罩避免沿岸混入海底高程，吐鲁番等陆地负高程保留。
- 高差订正：Open-Meteo 已把温度下推到请求点的 DEM 高度，因此先用 `T参考 = T节点 + 0.0065 × z节点` 归算参考高度，再逐日四邻双线性插值，最后 `T格点 = T参考插值 − 0.0065 × z格点`。没有重复叠加整段海拔降温。[Open-Meteo 文档](https://open-meteo.com/en/docs)
- 对每个细格独立判季与推算预报。缺少任一四邻天气节点或连续完整日的区域保持缺测，不跨数据洞填补。南海附图只示位置。

1°是气温采样间距，0.1°是地形辅助显示间距，**不等于 10 km 气温观测/预报精度**。固定 6.5°C/km 递减率不能表达局地逆温、坡向或冷空气堆积，仍属于原型级地形辅助模型估算。

## 平滑与颜色

地图改为预计算的 SVG 分级等值面，放大时不再把最近邻 PNG 方格放大。

- 温度：按连续滑动均温的固定阈值生成等值面，用线性插值定位等温边界，保持 12 档颜色及 10°C、22°C 分界。[D3 等值面说明](https://d3js.org/d3-contour/contour)
- 季节：各分类使用独立二值掩膜的 marching squares 轮廓，边缘在不超过 0.12 个格距内保守修圆。季节编号没有大小顺序，不对编号做连续插值。
- 换季：按“当前季节 → 目标季节”分别生成进行中、预报预计完成曲面。进行中色更靠近目标季节，预报预计色更靠近当前季节；例如秋→冬用紫色 `#8754b0` 表示进行中、深红 `#b7354f` 表示预报预计完成。
- 方向区分：入秋进行中使用赭橙 `#bc6b27`，与预计入冬的深红拉开色相；预计返夏使用橄榄金 `#aaa33b`，与预计入秋的橙色区分。
- 季节交汇处用原分类底图承接，独立有效区域裁剪保留缺测洞。没有 KDE、颜色归一化或模糊混色。

平滑边界是格点之间的显示近似，不增加实际气象信息。点选数据和行政归属仍对齐原始显示格点；温度图不叠换季颜色，季节图可开关换季标记。

## 行政归属与统计

使用真实县界做构建时点包含查询，显示选中格点实际所在的“省 · 市 · 县（区）”；直辖市去重。无县界覆盖时仅回退至真正包含该点的省级地区，海域不会借用最近县名。坐标作为副标题保留。

行政参考含 **2,874 个单元、369 个地级与直辖汇总**。边界来自 [DataV.GeoAtlas 公开历史区划](https://help.aliyun.com/zh/datav/datav-7-0/user-guide/datav-geoatlas-widgets/)，显示为 GCJ-02，天气和格点查询为 WGS84，二者分开转换。公开资料有 2,870 个县区及 4 个无下辖县区城市（东莞、中山、儋州、嘉峪关）；台湾缺县界时仅标省级归属，独立天气格点仍覆盖。

县级参考按县内代表点计算，不表示全县均温；地级主季按有效县区数量判定，数量相同显示多季并列，均温为有效代表点等权平均。县级数量比例不是面积比例。县级表、地级表支持搜索、筛选、分页、定位和 CSV 导出，原“县级参考 / 重点城市”地图切换及独立城市加载入口已移除。

## 滑标参考与时效

参考 [GB/T 42074—2022《气候季节划分》](https://openstd.samr.gov.cn/bzgk/std/newGbInfo?hcno=2CC96F656DE7E1641FEA09766A87FDD3)：当天及之前 4 天计算滑温，入春 ≥10°C、入夏 ≥22°C、入秋 <22°C、入冬 <10°C，连续 1–4 个滑标达标为观察，第 5 天完成参考初判。缺测和日期断档中断过程。

历史只使用北京时间已结束的完整日。当日和未来 7 日分开保存，旧预报不会随日期流逝自动变成历史；预报预计完成不是实际换季结论，历史回看不叠当前预报。资料更新时间显示为应用获取时间，不宣称模式起报时次。

尚未实现完整国家标准业务判定：没有 1991–2020 常年日温，未执行偏早二次判断、正式稳定通过和无冬/无夏校正。短历史会出现初始估计，春秋方向使用上/下半年辅助规则，不能替代官方入季结论。边界也不保证包含最新区划调整。

Open-Meteo 免费接口用于非商业原型，调用配额按位置和时间跨度计入；更新器逐日增量、断点落盘、共享下载互斥，正式使用应核对[现行许可与配额](https://open-meteo.com/en/pricing)。
