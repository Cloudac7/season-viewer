# 四时 · 中国季节地图

React + TypeScript + Vite 前端。默认使用独立 Open-Meteo 规则采样与真实 DEM 地形生成逐日气温场，再逐格计算滑标参考季节、进行中及预报预计完成的换季过程。季节边界可穿过行政区，西部大县内部能呈现山脉、盆地和河谷的差异。保持离散季节色阶，默认隐藏县界白线；另保留县级代表点、地级汇总与重点城市视图。

已移除国家气象站图层、名录、实况导入及旧的 244 点网格。当前独立气温采样为 **1°、1,265 点**，地形显示网格为 **0.1°、631×361**；行政参考包含 **2,874 个单元、369 个地级与直辖汇总单位**，另保留 67 个重点城市。细显示网格不是实际天气分辨率。

## 运行与检查

需要 Node.js 20.19+ 或 22.12+。

```sh
npm install
npm run dev                    # 默认 http://127.0.0.1:5173/
npm test                       # 气候判定、预报隔离、县界、坐标与数据质量测试
npm run build                  # TypeScript 与生产构建，输出 dist/
npm run preview                # 静态构建预览
npm run data:counties:update    # 更新共享县级模型快照，需要联网
npm run data:counties:import    # 重新导入公开县界、校验代表点，需要联网
npm run data:update            # 更新 67 个重点城市模型快照
npm run data:grid:update       # 更新独立规则气温快照，需要联网
npm run data:grid:import       # 生成默认 1°独立采样目录
npm run data:terrain:import    # 导入真实 Terrarium DEM，缓存公开瓦片
```

## 气象格点填色与地形处理

气象业务通常先对站点、雷达、卫星、数值模式等资料进行质量控制、分析和融合，形成气象格点场，再按阈值分级填色。行政边界主要用于定位与统计，并不决定温度场边界。参考：[中国气象局多源格点融合产品说明](https://www.cma.gov.cn/2011xwzx/2011xqxkj/2011xkjdt/202205/t20220518_4835961.html)。本项目借鉴这一处理顺序，**未接入或冒充官方多源实况融合产品**。

1. 独立采样：按 WGS84 规则格网在中国陆地及周边缓冲区设置 1,265 个 1°位置。目录不以县中心代替采样，因此西部大县内仍有多个气温节点。可用 `npm run data:grid:import -- --step=0.5` 重建更密目录；会改变目录 ID，需重新下载匹配快照，并核对调用额度。
2. 高度一致：Open-Meteo 默认使用 90 m DEM 对气温下推，并返回所用高程。先用 `T参考 = T节点 + 0.0065 × z节点` 归算参考高度，四邻节点对每个历史日和预报日分别双线性插值，最后用 `T格点 = T参考插值 − 0.0065 × z格点` 按 DEM 高程订正。不会重复叠加完整海拔降温。[Open-Meteo 文档](https://open-meteo.com/en/docs)
3. 真实地形：从 [AWS Terrain Tiles](https://registry.opendata.aws/terrain-tiles/) 获取 117 张 z6 Terrarium PNG，依照[官方编码格式](https://github.com/tilezen/joerd/blob/master/docs/formats.md)解码，重采样为 0.1°地形网格；保存瓦片 SHA-256、来源、时间和重采样方法。陆海遮罩避免沿岸混入海底高程，吐鲁番等陆地负高程保留。
4. 逐格判季：每个细格独立使用连续完整日温计算滑标，并独立推算未来 7 日换季过程。**不对季节编号、换季状态或颜色进行空间插值，不做 KDE 或归一化混色。** 缺少任一四邻气温节点、所选日期或连续日温的区域保持灰色，禁止跨缺测洞填补。
5. 绘图：后台 Worker 计算紧凑格点数组，最近邻重投影为离散色块，裁切到真实省域轮廓。县界只作可选定位图层，点击地图获取对应细格的气温、地形和过程；另可切换“县级参考”作对照。南海附图只示位置，不伪造网格范围外的温度。

这是原型级地形辅助温度场：1°约为几十至百公里的采样间距，0.1°仅为显示/地形采样间距，**不代表 10 km 气温观测或预报精度**。固定 6.5°C/km 递减率无法表达局地逆温、坡向、冷空气堆积等过程，不等同于气象台的复杂地形客观分析、动态降尺度或官方入季结论。未来可在同一数据契约下接入更密的授权格点产品，提升实际信息量。

独立快照保存在 `weather-grid-weather.json`，包含逐节点高程、实际模式网格坐标、完整日温、独立预报和获取时间。Vite `GET /api/weather-grid-weather` 返回共享快照并按缺口启动后台增量更新；生产静态部署使用打包快照，需每日执行 `data:grid:update` 后重建发布。只读取快照，不由浏览器发起全国直接 API 请求。独立网格与县级更新器使用同一下载互斥锁；格点更新器记录额度并计入近期县级刷新，遇 429 保存断点后停止。其他服务/设备的调用无法自动统计，需要自行核对。

## 页面功能

- 默认地形气温格点、县级代表点参考、重点城市三个视图；春夏秋冬固定色块；滑动均温层采用固定 12 档温度色标，10°C、22°C 单独分界，跨日期可直接比较。
- 县名、所属市或 6 位区划码搜索与定位；地形图点击读取细格季节、DEM 高程和日温，县级参考图点击读取代表点。两种口径分别标注。
- 地图拖动、双击放大、加减缩放、重置与搜索定位；可缩放至 64 倍。键盘支持加减、方向键和 0。
- 默认隐藏县级白线与代表点，保留细灰省界及选区轮廓；可选“显示县界”“显示代表点”。同色县区以同色细描边消除渲染接缝，县级参考仍按真实县界查询。地形图缺少完整相邻气温点/连续日温时标灰；县级参考不借用邻县或重点城市数据。
- 换季使用“当前季节 → 目标季节”的离散过渡色阶，分别标记进行中、按当前 7 日预报预计完成。关闭“标记换季”恢复四季或温度底色，缺测始终标灰。图例、详情、换季观察、地级汇总与 CSV 同步区分预报结果。
- 县区列表、地级汇总、区域和季节筛选、分页、CSV 导出。
- 67 个重点城市独立模型参考、气温曲线、浏览器本地收藏与 CSV 导出。
- 县级日期范围按实际历史覆盖动态开放，需要所选日期之前至少 9 天连续日温。首次获取近 14 天，因此当前只开放最近几个完整日；以后随每日积累扩展，最多在页面回看 30 天。重点城市保留原有 30 天回看。
- 手机、平板与桌面布局；标准说明弹窗支持焦点限制与 Escape 关闭。

## 县界与代表点

边界来自 [DataV.GeoAtlas / 高德公开行政区边界](https://help.aliyun.com/zh/datav/datav-7-0/user-guide/datav-geoatlas-widgets/)，使用 `areas_v3` 行政目录和市级下辖县界，独立城市单元使用其公开城市轮廓。保留实际多边形与孔洞，使用 TopoJSON 共享边界和拓扑简化压缩，未用规则网格、Voronoi 或 KDE 生成县界。

资料包含 33 个省级地区的 **2,870 个县区及省直辖县级单位**，以及 **4 个没有下辖县级分区的城市**：东莞、中山、儋州、嘉峪关。后者在县级地图和列表中作为独立城市单元明确列示，不伪造区县。台湾县级边界未由本次数据源提供，因此县级参考保留省域灰色轮廓；独立气温格点覆盖台湾，重点城市层也有台湾城市参考。

这是源接口公开的历史区划版本，不保证与最新撤县设区或区划调整一致。元数据保存数据源、抓取时间、`areas_v3` 版本说明、原始文件 SHA-256、坐标系及代表点选取方法；源接口未提供统一的区划修订日期，不能把抓取时间当作区划生效日期。DataV 官方说明其数据供学习交流，进一步使用应核对来源许可。

每个单元优先使用其行政中心坐标；若中心落在县界外，改用经过面内校验的几何代表点。所有代表点在拓扑简化前后都检查是否仍位于对应多边形内。原始边界与显示坐标使用 GCJ-02，Open-Meteo 查询点转换为 WGS84，二者分开保存；不会直接把显示坐标作为模型查询坐标。[DataV 坐标说明](https://help.aliyun.com/zh/datav/datav-7-0/user-guide/map-data-format-1)

本地资料：

```text
public/data/counties.json       单元目录、所属省市、显示/查询坐标、来源元数据
public/data/counties.topo.json  按单元代码关联的真实县界
public/data/county-weather.json 县级代表点模型日温共享快照
public/data/china.json          省域轮廓及南海附图
public/data/weather-grid.json   独立 WGS84 规则气温采样目录
public/data/weather-grid-weather.json 独立规则采样模型快照
public/data/terrain.json        0.1°真实高程与来源校验信息
```

原始下载缓存在 `data-sources/datav/`，不随生产构建发布。导入器会核对目录和边界的一一对应关系，缺失几何时中止，而不是构造替代县界。

## 模型数据与刷新

县级日温使用 [Open-Meteo Forecast API](https://open-meteo.com/en/docs)，请求 WGS84 坐标、`temperature_2m_mean` 与 `timezone=Asia/Shanghai`。过去日期是归档预报模型日温，**不是地面实测**。67 个重点城市另保留历史再分析与近期模型序列。

首次以每批 40 个位置获取过去 14 天和今起 7 天模型预报；只使用已结束完整日进行当前季节判定。当日及未来数据单独保存在 `series.forecast`（`issuedAt`、`days`），历史保存在 `series.days`。曲线虚线展示后续模型数据。之后请求最近 2 天的重叠序列；历史缺口超过 2 天则重新获取 14 天，最多保留 400 天。旧快照中未结束的获取当日日温不会随着日期流逝自动变成历史。缺少最近连续 9 个完整日的批次不替换旧记录。目录代码、查询坐标、日期唯一性、温度范围与逐县更新时间均做校验。

县级季节依据完整日更新，不需要每小时为全国重新请求。更新器检查各代表点是否已有最近完整日日温和今日获取的完整 7 日预报，两者都有则跳过；首次批量同步可能需要数分钟，每批落盘，所以中断后可继续。锁文件防止重复执行；失败保留已下载记录，并对缺测县区保持灰色。

**本地开发**：Vite 的只读 `GET /api/county-weather` 返回共享快照。发现新完整日或今日 7 日预报尚未覆盖时，在本机后台启动更新器，浏览器只轮询快照，不直接向 Open-Meteo 发起全国全量请求。正常每小时检查快照，后台补齐期间每 15 秒读取进度；刷新按钮重新读取共享快照，同日已完整的代表点不会重复抓取。

**静态生产部署**：托管 `dist/` 即可。没有本地开发 API 时，自动读取打包快照；需由部署环境每日执行 `npm run data:counties:update` 并重新构建/发布，或把同一数据契约放到自有后端。未更新的静态快照会保留原更新时间，缺少所选日期的县区标灰，不宣称已获取新实况。页面关闭时本地开发 API 不会主动启动新一天更新。

Open-Meteo 有调用配额，批量位置和时间跨度会计入调用量。当前更新器限速分批、按完整日增量更新；免费服务用于非商业原型。正式服务应核对 [现行许可与配额](https://open-meteo.com/en/pricing)。数据来源按 CC BY 4.0 标注。

## 换季颜色与预报口径

图式参考中央气象台的[逐时气温](https://www.nmc.cn/publish/observations/hourly-temperature.html)和[降水量实况](https://www.nmc.cn/publish/observations/hourly-precipitation.html)区域分级填色：增强色块层次、弱化行政线网，图例与填色使用同一套离散颜色。地形图先插值逐日气温再判季，县级参考按代表点判季；两者都不对季节类别插值或混色。

- 各方向使用季节代表色之间的两个离散色阶，不使用连续归一化混色。地图图例按当前筛选中出现的方向动态显示，详情、列表、观察卡和点位沿用相同配色。

| 换季方向 | 进行中 | 按预报预计完成 |
| --- | --- | --- |
| 秋 → 冬 | 深红 `#b7354f` | 紫 `#8754b0` |
| 夏 → 秋 | 橙 `#df793a` | 砖红 `#cb4c3c` |
| 春 → 夏 | 黄绿 `#b5c846` | 金黄 `#e2b22f` |
| 冬 → 春 | 蓝绿 `#48b6b2` | 绿 `#45a568` |

- 反向过程也有相应方向色阶，配置位于 `src/data.ts` 的 `TRANSITION_PALETTES`。
- “进行中”：截至所选完整日，连续达标 1–4 个滑动均温，预报尚未给出可用的完成结果。“预报预计完成”：今起 7 日内预计达到第 5 个连续滑标达标日；优先使用该方向的预报色阶。既可来自正在进行的过程，也可来自预报中新发并完成的过程，不会把当前季节提前换为目标季节。
- 详情与 CSV 的“预计确认日期”是预计达到第 5 次连续达标的日期，不是回溯的入季起始日。`issuedAt` 是本应用获取预报的时间，不宣称数值模式起报时次。
- 只在最近完整日视图叠加今日获取的预报；历史回看不使用当前预报。今起 7 日须完整连续且无空值，过期、缺失、当前过程被打断，或确认后剩余预报窗口出现反向过程时，不显示预计完成。预报结果随模型更新变化，不等同于实际或官方换季确认。
- 滑动均温层开启标记时，同样优先使用两种换季颜色；关闭标记即可读取温度底色。重点城市层使用相同颜色，省域换季色只表示已覆盖城市中的信号，不代表全省一致。

## 县级与地级口径

- “县级参考”视图颜色表示**县内代表点参考季节**，不是全县实测季节或全县面积均温；默认“地形格点”视图在县域内逐格独立计算。
- 地级汇总包含直辖市、省直辖县级单位和港澳。主季按有效县区中数量最多的季节判定，相同数量显示“多季并列”；筛选时保留并列季节。
- 地级均温为有效县级代表点 5 日均温的等权平均；缺测不作零值参与。它不是面积加权或人口加权均温。
- 县级数量占比、地级多数季节都不是季节覆盖的面积占比。67 个重点城市为独立坐标查询，可能与所属地级汇总不同，页面分开标注。

## 滑标参考与局限

参考 [GB/T 42074—2022《气候季节划分》](https://openstd.samr.gov.cn/bzgk/std/newGbInfo?hcno=2CC96F656DE7E1641FEA09766A87FDD3)：

1. 当天及之前 4 天的日温平均得到每日 5 日滑动均温。
2. 入春 ≥10°C、入夏 ≥22°C、入秋 <22°C、入冬 <10°C。
3. 连续 1–4 个滑动均温达标时观察，第 5 天完成参考确认，并从对应 9 天日温回溯首个达标日。
4. 缺测或日期断档中断连续过程；未来数据不参与历史判定。

**未完整实现国家标准的业务判定。** 没有 1991–2020 常年日温，未执行偏早 15 天以上的二次判断、正式稳定通过及无冬/无夏校正。首次县级短历史可能无法还原此前已确认的季节起始日，页面明确显示初始估计，后续历史积累可改善但不能替代气候常年校正。

现有辅助规则在连续 5 天反向越界后重新判定；春秋方向使用上/下半年；尚未检出夏/冬过程时以 8 月 1 日、1 月 1 日作展示用衔接。这些规则不等同于标准二次判断，不能替代官方入季结论。
